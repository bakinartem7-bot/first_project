# sorting-project

Командный учебный проект по Java 21: работа с коллекцией объектов `Car` через
консольное меню — заполнение, сортировка, поиск и сохранение в файлы.

## Требования к окружению

- **JDK 21** — задан toolchain'ом в `build.gradle`
  (`languageVersion = JavaLanguageVersion.of(21)`); Gradle подставит JDK 21
  автоматически.
- **Gradle Wrapper** — в репозитории есть `gradlew` / `gradlew.bat`,
  дистрибутив Gradle 9.3.0 скачивается автоматически при первом запуске.
- Кодировка исходников и вывода — UTF-8 (настраивается в `build.gradle`).

## Сборка и запуск

Windows:

```
gradlew.bat run      # запуск приложения
gradlew.bat test     # запуск тестов
gradlew.bat build    # полная сборка
```

Linux/macOS:

```
./gradlew run
./gradlew test
./gradlew build
```

Точка входа: `astonteam.sorting.Main` (см. `application { mainClass }`).

## Формат входного файла

Текстовый файл в кодировке **UTF-8**, по одному автомобилю на строку, поля
разделены символом `;`:

```
мощность;модель;год
```

Пример (`test_cars.txt`):

```
150;Toyota;2015
100;Audi;2018
```

Правила разбора (реализованы в `io.CarLineFormat` и `fill.FileFiller`):

- должно быть ровно три поля, разделённых `;`;
- **мощность** — целое число от 1 до 2000;
- **модель** — непустая, не длиннее 50 символов, без символа `;` и
  управляющих символов;
- **год** — целое число от 1886 до 2026;
- пустые строки пропускаются;
- некорректная строка отклоняется целиком: выводится сообщение с её текстом,
  файл не загружается, происходит возврат в меню.

Файл `bad_cars.txt` в корне — пример файла с ошибочными строками.

## Меню

**Главное меню:**

1. Заполнить коллекцию
2. Показать текущую коллекцию
3. Сортировать коллекцию
4. Поиск автомобилей
5. Подсчитать вхождения автомобиля (многопоточно)
6. Показать историю операций
7. Сохранить коллекцию в файл (перезапись)
8. Выход

**Заполнение (пункт 1)** — `console.FillMenu`:

1. Заполнить вручную — запрашивается количество, затем для каждого автомобиля
   по порядку вводятся мощность, модель и год;
2. Заполнить случайно — запрашивается количество, автомобили генерируются
   случайно (`fill.RandomFiller`);
3. Заполнить из файла — запрашивается путь к файлу (`fill.FileFiller`);
4. Назад в главное меню.

**Показать коллекцию (пункт 2)** — `console.CollectionMenu`: выводит все
автомобили текущей коллекции в читаемом виде
(`Мощность: 100; Модель: Audi; Год: 2002`) или сообщение о пустой коллекции.

**Сортировка (пункт 3)** — `console.SortingMenu`:

1. Сортировка вставками (`sort.InsertionSort`);
2. Сортировка слиянием (`sort.MergeSort`);
3. Сортировка автомобилей с чётной мощностью вставками
   (`sort.EvenPowerInsertionSort`);
4. Сортировка автомобилей с чётной мощностью слиянием
   (`sort.EvenPowerMergeSort`).

Для пунктов 1–2 дополнительно выбирается поле сортировки: **Мощность**,
**Модель** или **Год**. Для пунктов 3–4 сортировка выполняется по мощности.
После сортировки выводится статистика (алгоритм, поле, сравнения, перемещения,
время) и результат; предлагается дописать отсортированную коллекцию в
`results/history.txt`.

**Поиск (пункт 4)** — `console.SearchMenu`:

1. По мощности; 2. По модели; 3. По году; 4. По всем данным; 5. Назад.

Поиск по модели регистронезависимый. При наличии совпадений предлагается
дописать найденные автомобили в `results/history.txt`.

**Подсчёт вхождений (пункт 5)** — `console.CountMenu`: запрашивается автомобиль
и выводится число его вхождений в коллекцию (`search.CarCounter`, многопоточно).

**Показать историю (пункт 6)** — `console.HistoryMenu`: выводит содержимое
`results/history.txt` или сообщение о том, что история пуста.

## Файлы результатов

- `results/cars.txt` — сохранение всей коллекции **с перезаписью** (пункт 7);
- `results/history.txt` — **дописывание** (APPEND) результатов сортировки и
  поиска с шапкой (название действия и дата);
- каталог результатов по умолчанию — `results` относительно рабочего каталога
  запуска; переопределяется системным свойством
  `-Dastonteam.results.dir=<путь>`;
- перед перезаписью `cars.txt` запрашивается подтверждение, а пустая коллекция
  не сохраняется — случайное действие не уничтожит уже сохранённые данные;
- запись выполняется через временный файл и атомарное перемещение, поэтому
  сбой процесса не оставит частично записанный файл; остаточный `.tmp`
  удаляется.

| `MAX_CAPTION_LENGTH` | 100 | максимальная длина заголовка меню |
| `MAX_MENU_ITEM_ID` | 999 | максимальный номер пункта меню |

## Поведение при неверном вводе

- нечисловое значение, пустая строка, строка длиннее 256 символов или ответ,
  не являющийся «да/нет», повторяют запрос и **не завершают программу**;
- при накоплении 5 ошибок во время ввода одного автомобиля
  срабатывает `AttemptsExceededException` —
  программа выводит ошибку и возвращается в меню;
- после успешного создания
  автомобиля счётчик ошибок сбрасывается;
- некорректные данные автомобиля отклоняются, ввод автомобиля повторяется;
  модель не может содержать `;` (разделитель полей файла) и управляющие
  символы — иначе сохранение всей коллекции было бы невозможно;
- ошибки загрузки/сохранения файла перехватываются в `Main` — выводится
  сообщение и происходит возврат в меню;
- конец входного потока (Ctrl+Z в Windows / Ctrl+D) завершает программу
  штатно, без исключений.

## Тесты

JUnit 5 (`junit-bom 5.11.4`), запуск через `./gradlew test`.
Покрыто **27 тестовых классов, 242 теста**: валидация, модель, коллекция,
консольный ввод и меню, все источники заполнения, формат строки, сохранение
(включая APPEND и UTF-8), сортировки по всем полям, поиск, статистика,
сквозные сценарии `Main` (`MainTest`, `MenuScenarioTest`).

## Исправленные ошибки

- счётчик неудачных попыток не сбрасывался при успешном разборе
  (`markSuccess`), из-за чего лимит попыток не срабатывал;
- добавлена явная проверка отрицательной мощности с понятным сообщением;
- добавлена проверка длины модели (`Limits.MAX_MODEL_LENGTH`) в валидаторе;
- добавлен режим дописывания результатов (APPEND) без затирания файла.
